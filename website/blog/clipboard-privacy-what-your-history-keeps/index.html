Clipboard Privacy: What Your History Keeps and How to Control It

2026-10-19 · sabaoongfx · 6 min read

The clipboard is where sensitive things pass through. You copy a password from a password manager, a one-time code from a message, an address, a bank reference, a private paragraph. Normally the next copy overwrites it and it is gone. A clipboard history changes that on purpose: it keeps what you copied so you can use it again. That is exactly what makes it useful, and exactly why it deserves a few minutes of thought before you install any such tool, ours included.

What a clipboard history actually stores

Anything you copy while the manager is running. Text, including text you did not mean to keep. Images, including screenshots of private windows. If history is saved between sessions, that record sits on your disk until you remove it. In Open Clipboard Manager it is a JSON file plus PNG files in your per-user data folder, so anyone who can read your user profile can read it, and it is as safe as the rest of that folder and no safer. There is no encryption layer, and we would rather say so than imply one.

Settings that matter

SettingWhat it doesWhy you might change it
Remember history between sessionsWrites entries to disk so they survive a restart.Turn it off to keep history in memory only; quitting the app discards it.
Record imagesKeeps copied pictures and screenshots.Turn it off if you screenshot sensitive windows.
History size (1–1000)How many entries are kept before the oldest is dropped.A smaller number means a secret ages out sooner.
PauseStops recording until you resume.Use it right before copying something you do not want kept.

Two toolbar actions complement these. Remove (or the Delete key) deletes the selected entry, and Clear empties the whole history. If you copied a password by mistake, removing that one entry takes a second.

Password managers and the clipboard

Many password managers clear the clipboard after a short delay for exactly the reason above. A history tool that has already recorded the value defeats that protection, because the manager can only clear the live clipboard, not another program’s copy. If you use a password manager that copies passwords, the safest habits are to pause the history first, or to delete the entry afterwards. Better still, use the manager’s auto-type or browser integration, which never touches the clipboard at all.

What stays local

Open Clipboard Manager has no telemetry, no account and no network access. It does not sync history between devices, upload anything, or check for updates in the background. The trade-off is that you do not get cross-device history; the benefit is that there is nowhere for your clipboard to leak to. You can check this yourself: the code is MIT-licensed and public, and the app’s own internals post lists every moving part.

Actions are shell commands

There is one more thing to know. The right-click actions feature runs a command that includes the text you copied. Before the text is placed in a command it is stripped of quotes, backslashes and line breaks (and, on macOS, $ and backticks), which blocks the usual tricks for sneaking in extra commands. Even so, an action is a shell command, so only add actions you wrote or trust, and be careful with ones that pass the clipboard to programs that interpret it.

A sensible setup

  1. Decide whether you need history across restarts. If not, turn off remember history between sessions.
  2. Set the history size to what you actually use. Fifty entries covers most days.
  3. Turn off image recording if you take screenshots of private pages.
  4. Pause before copying anything secret, or delete the entry right after.
  5. Keep your disk encrypted, since the history file is only as private as your profile.

None of this makes a clipboard history risky to use. It makes it a tool whose behaviour you should understand, which is easier when it is small, local and open source. You can read how it works in the repository, or see the full feature list on the Open Clipboard Manager page.
