CPU Usage Explained: Cores, Threads and What That Percentage Means

2026-10-11 · sabaoongfx · 3 min read

CPU percentage looks like the simplest number in a task manager. It is also one of the most misread. To use it well, you need three ideas: cores, threads and the thing the percentage is measured against.

Cores and logical processors

A modern processor has several cores, each able to run instructions independently. Many cores can also present themselves as two logical processors (simultaneous multithreading), so a six-core chip may appear as twelve. Your operating system schedules work across all of them. When a monitor says “100 percent,” the key question is: 100 percent of what?

Two conventions

  • Percent of the whole machine. 100 means every logical processor is saturated. A program fully using one core on a twelve-processor machine shows about 8 percent. The Windows Task Manager works this way for its main CPU figures since the 24H2 change, and so does Open Task Manager since version 0.4.2 (the story).
  • Percent of one core. 100 means one core is fully used, and a multi-threaded program can exceed it: 400 means about four cores’ worth of work. Many Unix-style tools follow this convention. Open Task Manager did too until version 0.4.2, when we switched to the whole-machine share so process rows add up to the total at the top, as they do in Windows.

Neither is wrong. They answer different questions: “how busy is the machine?” versus “how much of a core is this program consuming?” Always check which one your tool is using before comparing numbers.

Single-threaded bottlenecks

A program that uses only one thread can use at most one core. On a twelve-core machine that is about 8 percent overall, so the system looks nearly idle even though that program is as fast as it can possibly go and still feels slow. If a program is sluggish while the overall chart is low, look at its per-core or per-process figure. One core pinned at 100 percent is the clue.

What “normal” looks like

  • Spikes. Short bursts of 50 to 100 percent when you open something are expected.
  • Idle. A resting desktop should hover in low single digits.
  • Sustained load. Anything above about 30 percent for minutes, when you aren’t doing demanding work, deserves a look.

Laptops add a wrinkle: speed changes constantly. A core at half speed running flat out reports as busy, so the same percentage can mean different amounts of work. Some tools adjust for this (Windows’s utility-style metric does) and others don’t.

Finding the culprit

  1. Open the Processes tab and sort by CPU. Let it settle for ten seconds, since it jumps around.
  2. Identify the top entry and check whether it is an app you are using.
  3. If it is an unfamiliar helper, look it up. Indexing, backups, antivirus scans and updates all legitimately use CPU for a while.
  4. If it never settles, check the Performance tab for the overall pattern and restart the app, or see how to end a stuck process safely.

Remember the refresh rate

Every monitor samples at an interval; ours refreshes every 1.5 seconds. Percentages are averages over that window, so very short bursts can fall between samples. For tracking down intermittent problems, watch the chart for a minute rather than reading one instant. And if you see many more entries than expected, see process versus thread.
