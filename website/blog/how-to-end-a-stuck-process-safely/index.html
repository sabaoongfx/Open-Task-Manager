How to End a Stuck Process Safely: SIGTERM, SIGKILL and End Task

2026-10-11 · sabaoongfx · 3 min read

Every computer user meets a frozen program eventually. The window won’t respond, the spinner never stops, and closing it does nothing. Ending its process is the standard fix. Done right it is safe; done carelessly it can lose unsaved work or destabilise your session. Here is how to do it well.

Ask first, force second

There are two levels of ending a process, and the difference matters.

  • A polite request. On Unix-like systems this is the SIGTERM signal. It tells the program “please shut down,” and a well-behaved program saves state, closes files and exits. Windows’s equivalent is closing the main window.
  • A forced kill. SIGKILL on Unix, or forced termination on Windows. The operating system removes the process immediately, with no chance to clean up. It always works on a process you own, but unsaved data is lost, and temporary files may be left behind.

The sensible order is to wait a minute (some programs are busy, not frozen), try to close the window normally, then ask politely, and only then force. In practice, Open Task Manager’s End task action is a forced kill of the selected process; it is the one real action on your system that the app performs, so use it knowingly.

Steps in a task manager

  1. Find the right row. Use search to filter by name. If the app is grouped, expand it to see its helpers.
  2. Check the details. Confirm the name and that it is owned by you. The Details tab shows PID and user.
  3. Right-click and choose End task. In the terminal UI, select the row and use its kill prompt, which asks you to confirm.
  4. Confirm the result. The row should disappear on the next refresh. If it comes back immediately, something is restarting it; look at the Services and Startup tabs.

Ending a whole app versus one helper

Ending the main process of a grouped app usually closes the rest. Ending a single helper can make the app show an error page or restart that part. If an app is partly broken, such as one browser tab that has crashed, ending just that helper is a gentler fix.

What not to end

  • System processes. On Windows, entries running as System that you can’t identify; on Linux, systemd, your display server or session manager. Ending these can log you out or freeze the machine.
  • Anything you don’t recognise. Search the name before acting.
  • Processes with unsaved work. If you can, copy the content out first.

The operating system will often refuse if you lack permission, such as ending another user’s process or a protected one. That refusal is a safety feature, not a bug. Don’t reach for administrator rights unless you understand why you need them.

If it keeps getting stuck

Repeated hangs deserve diagnosis, not repeated killing. Watch the process in the monitor first. Does it use a lot of CPU (a loop), steadily grow in memory (a leak), or sit at zero while the disk is busy (a disk problem)? Update the software, disable add-ons, and note what you were doing when it froze. That detail is what a bug report needs.
