How to Find a Memory Leak With Just a Task Manager

2026-10-11 · sabaoongfx · 3 min read

A memory leak is a program that keeps asking for memory and never gives it back. Left running, it grows until the system slows, other programs are killed, or the machine runs out. You don’t need a debugger to spot one. A task manager and a bit of patience are enough to tell a leak from normal behaviour.

Leak or just busy?

Memory use rising is not proof of a leak. A browser grows as you open pages. An editor grows as you open files. Caches deliberately fill up. The distinguishing feature of a leak is that memory keeps climbing when the workload isn’t changing and doesn’t come back down when the work is done.

The method

  1. Pick a suspect. Sort the Processes tab by memory. Look for the process you suspect, usually something you leave open for days.
  2. Record a start value. Note its memory, and the time. Group by app so helpers add into one total.
  3. Hold the workload steady. Don’t open new files or pages. Let it idle or repeat one simple action.
  4. Check at intervals. Look again after ten minutes, an hour, a day. A steady upward slope with nothing changing is the signature.
  5. Test the reset. Close the work inside the program (the document, the tab). If memory doesn’t fall, that is more evidence. Then restart the program; if it drops to the baseline and begins climbing again, the leak is in that program.

The Performance tab helps with the machine-wide picture. If total memory climbs in step with one process, you have found your suspect. Open Task Manager’s App history tab, which accumulates CPU time per app since launch, adds a second clue: a leaking program that is also spinning will stand out.

Common false alarms

  • Caching. Programs that cache aggressively look like leaks until they hit their cap. Watch for a plateau.
  • Garbage-collected runtimes. Languages that clean up periodically show a sawtooth: climb, drop, climb. That is normal; a rising baseline across the drops is not.
  • Shared pages. Resident memory counts shared libraries. A jump when another program loads the same library isn’t a leak (see memory explained).

What to do once you’re sure

  • Update. Leaks are common bugs and often fixed in newer releases. Check the changelog.
  • Disable extensions or plugins. In browsers and editors, extensions are a frequent cause. Disable them one at a time and repeat the test.
  • Work around it. Restart the program on a schedule, or on a lightly used machine, when it passes a threshold.
  • Report it. Include your operating system, version, and the numbers from your test. A reproducible report with a slope and time is far more useful than “it uses too much RAM.”

Be careful about ending the wrong thing

If the leaking program is something you started, restarting it is safe. If it is a system process, don’t force-end it; restart the machine and report the issue. Our guide to ending processes safely covers the difference between asking a program to quit and forcing it.

The method works in any task manager. It’s slow, but it separates real defects from ordinary growth, and that saves you from chasing the wrong program.
