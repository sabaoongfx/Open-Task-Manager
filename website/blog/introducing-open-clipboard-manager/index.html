Introducing Open Clipboard Manager

2026-10-19 · sabaoongfx · 6 min read

You copy a link, then copy a paragraph, and the link is gone. Everyone has lost something this way: an address copied a minute ago, a command you needed twice, a screenshot you grabbed and then overwrote. A clipboard on its own holds exactly one thing. Clipboard history is the small fix for that, and it is one of those tools that feels optional until you have used it for a week.

Windows ships its own version, switched off by default and reachable with Win+V. Linux desktops mostly leave it to optional panel plugins, and macOS has nothing built in. Open Clipboard Manager is our attempt at one tool that behaves the same on all three: free, MIT-licensed, local-only, and styled after Open Task Manager so the two apps look like they belong together.

The problem it solves

The clipboard is a shared scratch space owned by whichever program last copied into it. When you copy again, the old contents are replaced. On Linux and macOS there is an extra wrinkle: on some systems the data is held by the program that copied it, so closing that program can empty the clipboard entirely. A history manager sits in the background, notices each change, and keeps a copy of its own so nothing disappears.

That sounds minor, but it changes how you work. You stop alt-tabbing back to the source for the thing you already copied. You can gather five snippets from five pages and paste them in order. You can copy something, copy something unrelated by accident, and still get the first one back.

What it does

  • Text and images. Screenshots and copied pictures are kept as thumbnails, and text shows its length. A preview pane on the right shows the full entry, so you can tell two similar snippets apart before pasting.
  • Search as you type. The search box is focused as soon as the window opens, so the common path is hotkey, a few letters, Enter. Typing image filters to pictures, and there is a separate Images tab as well.
  • Pick and paste. Enter or a double-click copies the entry back to the clipboard and pastes it into the window you came from. If you opened the window from the tray there is no previous window, so it only copies.
  • Remove, clear and pause. Toolbar buttons handle the housekeeping, and Delete removes the selected entry. Pausing is useful when you are about to copy something you do not want recorded.
  • Actions. Right-click an entry and the app offers the commands whose pattern matches it: open a URL in the browser, look up a bug number, show a file in Explorer or Finder. The idea comes from Xfce’s Clipman, and the rules live in a plain actions.json file you can edit.
  • Settings. Popup hotkey, history size from 1 to 1000, preview length, whether to paste after choosing, whether to remember history between sessions, whether to record images, and start at login.

One hotkey on every system

The default is the one you already know. On Windows it is Win+V, and while Open Clipboard Manager runs it replaces Windows’ own clipboard panel. On Linux it is Super+V on X11. On macOS it is Ctrl+Cmd+V, because Cmd+V is the system Paste shortcut and cannot be reused. You can change it in Settings, and the change applies immediately.

Wayland is the exception. It does not let ordinary applications grab a global key, so there you bind a shortcut in your desktop’s keyboard settings to Open-Clipboard-Manager-x86_64 --show. That command opens the window of the copy that is already running instead of starting a second one.

Private by design

A clipboard history is, by nature, a record of everything you copied, and that includes things you would not want recorded. So the design rule is simple: nothing leaves the machine. There is no telemetry, no account and no network access. History is stored as a JSON file next to PNG files for images, in your per-user data folder. If you would rather keep nothing on disk, turn off remember history between sessions and it lives in memory only. The privacy post goes through the settings worth knowing.

How it looks

The window follows Open Task Manager: a navigation rail on the left that can collapse, a card with a title and toolbar, a flat table, rounded controls, and light or dark colours that follow your system each time the window opens. It is built with Python and Tk, so it starts quickly and stays small, and it runs from a single file on each platform.

What it can’t do yet

Better to hear the limits from us than to find them yourself.

  • The macOS build is started and tested by CI on a real Mac, but nobody has used the clipboard, hotkey and paste on one yet. Expect rough edges and please report them.
  • There are no Intel Mac or ARM Linux builds yet.
  • The Windows and macOS builds are not code-signed, so SmartScreen or Gatekeeper may warn you the first time.
  • Actions are edited by hand in actions.json; there is no editor window.
  • The standard Tk table cannot draw rounded rows or scrollbars, and rendering on high-DPI screens could be sharper.

Get it

Windows is one portable .exe, Linux is one binary, and macOS is a zip for Apple Silicon. The download page has every file and picks the right one for your system, and the install section has the short setup steps, including the helper programs Linux needs. The source is on GitHub; if something breaks, open an issue with your operating system and what you expected to happen.
