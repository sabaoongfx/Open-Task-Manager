Introducing Open Task Manager

2026-10-11 · sabaoongfx · 6 min read

Almost everyone who uses a computer has opened a task manager at some point: the app froze, the fan started screaming, or the battery drained for no obvious reason. The Windows 11 Task Manager is a good answer to those moments. It groups processes by application, shows live graphs, and lets you end a stuck program in two clicks. The trouble is that it only exists on Windows, and you can’t read, change or audit it.

Open Task Manager is our attempt to keep what works about that design and fix those two limits. It is a free, MIT-licensed process and performance monitor for Linux, Windows and macOS, with the layout you already know. This post covers what it is, how it is built, what it can and can’t do today, and where it is going.

The idea

Linux has plenty of system monitors, and many are excellent, but they each have their own conventions. macOS has Activity Monitor, which looks nothing like either. Anyone who switches between operating systems, or who supports family and coworkers on different ones, ends up re-learning the same tool three times.

We wanted a single, familiar layout everywhere: a left-hand tab strip, a Processes list grouped by app, and a Performance page with CPU, memory, disk and network graphs. We also wanted it small, fast to start, and honest about what it does with your data. That last point gets its own post: Open Task Manager vs. the Windows Task Manager.

What’s in the app

  • Processes. Processes are grouped by application, so a browser with thirty helper processes appears as one expandable row. You can search, sort by any column, and end a task from the right-click menu or the keyboard.
  • Performance. Live rolling charts for CPU, memory, disk and network, updated every 1.5 seconds from real operating-system counters.
  • App history. Cumulative CPU time per application since the app was opened.
  • Startup apps. The programs configured to launch at login.
  • Users. Resource usage summed per user account, which is especially useful on shared machines and servers.
  • Details. The flat, per-process table (PID, status, user, CPU, memory) for when you want the raw list instead of the grouped one.
  • Services. The services configured on the machine.
  • Disk usage. A WinDirStat-style scan of a folder showing what is using the space as a treemap, a tree, a largest-files list or a breakdown by file type.

How it’s built

Open Task Manager is a Cargo workspace with three parts that share one backend.

  • core/ (otm-core) holds all data collection. It uses the sysinfo crate to read processes and hardware counters straight from the operating system, and keeps the rate and history state the graphs need.
  • src-tauri/ is the desktop app. It is a thin layer of Tauri commands over the core, with a React and TypeScript interface drawn in your system’s own webview.
  • tui/ is otm, the terminal version, built with ratatui. It calls the same core functions directly.

Because the app uses the system webview instead of shipping its own copy of Chromium, installers stay small and memory use stays modest. A tool whose whole job is to show you what is eating your RAM shouldn’t be one of the biggest items on the list. Release builds also enable link-time optimization and symbol stripping, which keeps the binary compact.

A terminal version: otm

The same eight tabs are available without a desktop at all. otm is a keyboard- and mouse-driven terminal UI meant for SSH sessions, servers, and anyone who lives in a terminal. It reads the same real data through the same backend, and it needs no Node.js and no graphical session:

cargo run -p otm

On Linux, every package we publish installs both programs: the desktop app in your menu and otm on your path.

Installing it

We publish signed apt and pacman repositories, so on Ubuntu, Debian, Mint, Pop!_OS and Arch the app updates through your normal package manager. There are also .deb, .rpm and AppImage downloads, a Windows installer (.exe and .msi), and macOS disk images for Apple Silicon and Intel. Every direct download is listed in the download section, and standalone otm archives are attached to each release.

What it can’t do yet

We’d rather you hear the limits from us than discover them in the app, so here is the honest list.

  • Ending a task is the only action that changes your system. Start/Stop on services and Enable/Disable on startup apps update the interface but don’t touch the real service manager or autostart entries yet.
  • The Services and Startup tabs read real data on Linux only. On Windows and macOS they are currently empty in the installed app.
  • App history resets when you close the app, because nothing is saved to disk.
  • Windows and macOS installers are not code-signed yet, so you may see a warning the first time you open them.

The roadmap tracks each of these, and the first two are the next priorities.

Get involved

The whole project is on GitHub. If you hit a bug, open an issue with your operating system and what you expected to see. If you want to help, the most valuable contributions right now are real service and startup control, testing on Windows and macOS, and the thread-counting fix. Since the code is open, you can also read exactly what the app does before you trust it with your machine.
