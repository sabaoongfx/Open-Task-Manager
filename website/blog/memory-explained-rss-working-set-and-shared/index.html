Memory Explained: RSS, Working Set, Shared and Cached

2026-10-11 · sabaoongfx · 3 min read

Few numbers cause more confusion than memory. You close everything, and the monitor says half your RAM is used. Two tools disagree by a gigabyte. A program seems to use more than it could. None of this means something is broken: it means “memory used” is several different things with the same name.

Virtual versus physical

Every process sees a large, private range of virtual memory, an address space the operating system maps onto real RAM only as needed. A program can reserve gigabytes of address space and touch very little of it. Monitors that show virtual size look alarming and mean little. What matters day to day is how much physical RAM a process is actually holding.

The common measures

  • Resident set size (RSS) on Linux and macOS. The amount of a process’s memory currently in RAM. It includes pages shared with other processes, such as libraries, so adding RSS across processes counts shared pages repeatedly.
  • Working set on Windows. The set of pages recently used and kept in RAM. It plays the same role as RSS and has a similar double-counting caveat. A related figure, private working set, excludes shared pages.
  • Shared memory. Pages used by more than one process. The same library loaded by thirty programs can sit in RAM once.
  • Private or unique memory. What would be freed if the process ended. It is the fairest measure of an app’s own cost, and harder to compute.

The monitor you use picks one of these. Open Task Manager shows per-process memory as reported by the operating system through sysinfo, a resident-memory style number, so summing many processes can overstate the true total. This is the same effect that makes thread listings inflate memory.

Why “used” is high on a healthy machine

Unused RAM is wasted RAM, so operating systems fill spare memory with cache: recently read files and data kept in memory so the next access is fast. Cache is released instantly when programs need the space. On Linux, the “free” command separates it out; on Windows, Task Manager shows it as “cached” or “standby.” A machine showing 90 percent used with most of it cache is working as designed.

That is why “RAM cleaner” tools are usually counterproductive. They discard the cache, so files you will need again must reload from disk, making the machine feel slower while the number looks better.

Signs of real memory pressure

  • The memory chart is pinned near the top and disk activity is high and constant, because the system is paging data to disk.
  • The machine stutters when switching between apps that were fine a moment ago.
  • Programs are closed or killed by the system. On Linux this is the out-of-memory killer, and its messages appear in the system log.
  • A single process’s memory grows steadily and never falls (a leak).

Reading a memory column well

  1. Look at the group total for an app, not one helper process.
  2. Watch the trend over minutes, not one instant.
  3. Compare against available memory, not total, since cache can be reclaimed.
  4. When two tools disagree, check which measure each uses before assuming one is wrong.

With that in mind, memory prices matter more than they did last year (here is why), and reading the numbers correctly is the first step to spending less of it.
