Reading the Network Graph: Which App Is Using Your Bandwidth?

2026-10-11 · sabaoongfx · 2 min read

A slow video call, a download that stalls, a data cap that vanishes: all of these start with the question “what is using my network?” A task manager can answer part of it quickly. This guide explains what the numbers mean, what they can't tell you, and where to go for the rest.

What the graph shows

The network section of the Performance view plots the data your machine is receiving and sending, summed across all of its network interfaces: Wi-Fi, Ethernet, virtual adapters. In Open Task Manager, the rates come from the operating system’s interface counters and are reported as bytes per second, refreshed every 1.5 seconds. You will usually see two lines: receive (download) and transmit (upload).

A few reading tips:

  • Bytes versus bits. Internet plans are advertised in bits per second; monitors often show bytes. Multiply by eight to compare. 10 MB/s is about 80 Mbit/s.
  • Download and upload are separate. A cloud backup shows as sustained upload. A video stream shows as sustained download.
  • Virtual interfaces count. VPNs, containers and virtual machines add interfaces, and traffic can be counted on more than one. If numbers look doubled, check the interface list.

Finding the application

The machine-wide graph tells you that something is using the network. Finding what is more variable. Some operating systems report network use per process; others, and some monitors, show only the totals. Windows Task Manager and Resource Monitor include a per-process network column. On Linux, per-process bandwidth generally needs a dedicated tool such as nethogs, which watches traffic by process. We don’t claim Open Task Manager attributes network use to individual processes; it shows interface totals, so use it to confirm a spike and another tool to name the culprit.

A practical routine:

  1. Watch the graph while you close apps one at a time. When the line drops, you found the source.
  2. Pause cloud sync, backups and updates first; they are the usual offenders.
  3. Check your browser: video, a stuck page, or a background tab can stream continuously.
  4. If the traffic continues with everything closed, a different device on your network may be responsible, so check your router’s client list.

Normal versus suspicious

Small, regular bursts are normal: time sync, update checks, notifications. What deserves a closer look is large, sustained upload from something that shouldn’t have a reason to send data, or steady traffic at night from an app you never use. Those patterns are worth investigating with the methods in how to check what an app sends over the network.

Limits of a task manager here

A throughput graph shows volume, not content or destination. It can’t tell you whether traffic is encrypted, where it is going, or whether it is wanted. Treat it as a smoke detector: it says there is something worth looking at, and the other tools say what. That is also why we make no claim about network contents on this site beyond what our code does, which is open for you to read.
