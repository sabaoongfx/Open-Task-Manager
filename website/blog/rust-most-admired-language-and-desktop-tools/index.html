Rust Is the Most Admired Language Again. Does It Matter for Desktop Apps?

2026-10-11 · sabaoongfx · 3 min read

The 2025 Stack Overflow Developer Survey, with more than 49,000 responses from 177 countries, again named Rust the most admired programming language, at 72 percent. Gleam followed at 70 percent, Elixir at 66 and Zig at 64. Cargo, Rust’s package manager, was the most admired cloud and infrastructure tool at 71 percent, and uv, a Python package manager written in Rust, scored 74 percent in the technologies category.

Numbers like these invite two lazy reactions: “everything will be rewritten in Rust” and “it is just hype.” Neither is right, and the useful answer sits in between.

What “admired” measures

The survey asks developers who have used a language whether they want to keep using it. So “admired” is a satisfaction score among people who already tried it. It says nothing about how many people use the language, and it is skewed toward people who chose Rust on purpose. A language that is hard to start with can score well because the people who got past the learning curve are happy.

That caveat matters, but the result has been consistent for years, and it lines up with other signals: Rust’s permanent place in the Linux kernel, the growing number of command-line tools written in it, and the wave of Python and JavaScript tooling that has moved to it for speed. The survey’s own Cargo and uv numbers fit the same pattern.

Why desktop software cares

Desktop programs have a different set of pressures from web services. They start often, they run alongside dozens of other programs, and users notice every extra megabyte. Rust gives three things that suit that environment:

  • Predictable performance. There is no garbage collector pausing the program, so memory use and latency stay steady.
  • Small, self-contained binaries. A release build can be a single executable with its dependencies compiled in.
  • Safety at the edges. Code that talks to the operating system is exactly where memory bugs hurt most.

The cost is real too. Rust has a steep learning curve, compile times can be long, and the graphical-interface ecosystem is younger than the options in C++, C# or JavaScript. That last point is why many Rust desktop apps pair a Rust core with a web-based interface, which is the approach we took. The tradeoffs of that choice are covered in Tauri vs. Electron: what the numbers say.

A practical way to read the survey

If you are choosing a language for a desktop tool, treat the survey as a tiebreaker, not a decision. Ask instead: Will the people maintaining this be comfortable in it in three years? Does the library you need exist? Can you hire or attract contributors? For a system monitor, the answers favoured Rust: the sysinfo crate already handles the per-platform differences in reading processes and hardware, and a single Rust core can feed both a graphical app and a terminal UI.

The honest summary is that Rust’s popularity is real, well-measured among its users, and backed by serious adoption in places that are hard to fake, like the kernel. It is not a guarantee of a good product. A badly designed tool in any language is still a badly designed tool.
