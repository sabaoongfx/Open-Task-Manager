top, htop, btop and otm: Choosing a Terminal System Monitor

2026-10-11 · sabaoongfx · 3 min read

If you manage a server over SSH, run a machine with no desktop, or just prefer a keyboard, a terminal system monitor is the tool you will reach for most. There are several good ones, and the right choice depends on what you value. Here is how the common options compare, including our own, which is the youngest and should not be assumed to be the best.

top

top ships with essentially every Unix-like system. That is its whole advantage: on a minimal server, a rescue shell or an unfamiliar machine, it is already there. It shows processes sorted by CPU, summary lines for load and memory, and a handful of interactive keys. The interface is austere and the learning curve for its commands is steeper than newer tools, but you can count on it.

htop

htop is the long-time favourite upgrade. It adds colour, per-core bars, a scrollable process list, a tree view that shows parent and child relationships, mouse support and easy kill and nice commands. It is mature, widely packaged and fast. If you want one tool to learn on Linux, this is the safe pick.

btop

btop leans into visuals: graphs for CPU, memory, disk and network on one dashboard, themes, and mouse control. It reads like a small control room. It tends to use more screen space and may need a modern terminal with Unicode support to look right. Its strength is giving a quick overall picture of the machine.

Glances

Glances, written in Python, collects a wide range of metrics and can run in a web or client-server mode, which is handy for watching remote systems. It is broader than a simple process viewer, at the cost of being heavier than the C and C++ tools above.

otm

otm is Open Task Manager’s terminal UI. Its angle is consistency: it presents the same eight tabs as the desktop app (Processes, Performance, App history, Startup apps, Users, Details, Services and Disk usage), reading from the same Rust data core. It supports keyboard and mouse input and groups processes by application. If you already use the graphical app or the Windows 11 Task Manager, the layout will be familiar. Install it with the desktop app on Linux, or download the standalone archive for your platform from the releases page.

It is also the least proven. It does not yet have htop’s years of polish, plugin-like flexibility or tree-style process view, and it shares the app’s known limits: its Services and Startup controls do not yet change the system, and App history resets when it closes. (Older versions also listed Linux threads as separate processes, explained here.)

A few habits that apply to all of them

  • Learn how to sort by memory and by CPU, and how to filter by name.
  • Know the difference between asking a process to quit and killing it (here).
  • Read the load and memory summary before blaming one process.
  • Don’t run monitors you haven’t verified as root on production systems without reading what they do.

There is no need to pick only one. Many administrators keep top as a fallback, htop as a daily driver and something else for dashboards. Try each for a week and keep the one that stays out of your way.
