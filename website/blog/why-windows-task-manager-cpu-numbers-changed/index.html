Why the Windows Task Manager's CPU Numbers Changed in 24H2

2026-10-11 · sabaoongfx · 3 min read

If you ever noticed that the Windows Task Manager showed one CPU percentage for a program on the Processes tab and a different total on the Performance tab, you were not imagining it. The two views used different calculations for years. In 2025, Microsoft changed the Processes tab to match, and the story is a good way to understand what a “CPU percentage” actually is.

Two metrics, one label

The older Processes tab used a metric called Processor Utility, which was designed to reflect how busy a core is relative to its current frequency and capabilities. The Performance and Users views used a different measure based on the share of time the processor spent working. Because they weren’t the same, a single heavily loaded core on a many-core machine could make the Processes tab look much busier than the overall figure suggested, and a program could even appear to pin the CPU at 100 percent when it wasn’t using it all.

What Microsoft did

Microsoft first tested a standardised formula in an Insider build in early 2025 and brought it to Windows 11 24H2 with the May 2025 update (KB5058411). The Processes tab now uses the same calculation as the Performance and Users tabs:

CPU % = (change in process CPU time) / (elapsed time x logical processors)

In plain words: how much processor time the program consumed, divided by how much was available across all logical processors. A program that fully loads one core of an eight-core machine now shows about 12.5 percent, which matches intuition. If you prefer the old figure, you can add the CPU Utility column on the Details tab by right-clicking a column header.

Not every tool agrees, either. Community explanations note that the Details tab and Sysinternals’ Process Explorer use Processor Time, which is a different basis. That is a secondary explanation rather than an official statement, but it matches the experience of seeing different numbers in different tools.

Reading CPU numbers anywhere

The lesson applies to every monitor, including ours. Before trusting a number, ask what it is relative to:

  • Relative to one core. Many Unix-style tools report 100 percent per core, so a busy multi-threaded process can read 400 percent on four cores. Open Task Manager used this convention for individual processes until version 0.4.2, when it moved to the whole-machine share so rows add up to the total, like Windows.
  • Relative to the whole machine. This is the style Microsoft now uses, where 100 percent means every logical processor is saturated.
  • Relative to frequency. Utility-style measures adjust for how fast the core is running at that moment, which can shift numbers on laptops that change speed constantly.

Practical advice

  1. Compare readings within one tool over time rather than across tools.
  2. Check the Performance chart for the overall picture before blaming one process.
  3. Watch for sustained load, not spikes. Brief jumps to a high percentage are normal.
  4. Remember the number of logical processors; it explains most of the surprise.
