Windows Recall and the Case for Software You Can Audit

2026-10-11 · sabaoongfx · 3 min read

When Microsoft first showed Windows Recall in 2024, the idea was simple: the computer takes a snapshot of your screen every few seconds so you can search your own history later. The reaction was not. Security researchers pointed out that anyone who got into your machine for even a moment could read a detailed record of everything you had done, and that early versions stored much of that data in plain text. Within weeks Microsoft changed course.

What changed after the backlash

Reporting at the time says Microsoft made Recall opt-in rather than on by default, required Windows Hello to access it, and added stronger encryption to the stored data. The company has said the data stays on the device. The UK’s Information Commissioner’s Office said it was talking with Microsoft about data protection. The current state of the feature is for Microsoft’s own documentation to say; we are describing the original controversy, not auditing today’s version, and you should check before relying on any of it.

The episode is useful whatever you think of Recall itself, because it shows how the trust problem works.

The trust problem with closed software

When a program is closed source, you trust three things at once: that the vendor describes it honestly, that the vendor builds it correctly, and that the vendor won’t change it later. Each is reasonable, and each is a promise rather than something you can check. Recall’s plain-text storage was caught by outside researchers who examined the running software, not because anyone could read the code.

Open source doesn’t remove the need for trust, but it changes what it rests on. Anyone can read the code, build it, and compare it with what is distributed. A change that added tracking would appear in the public history. That is verifiability, not virtue: an open project can still be careless, but its behaviour is checkable by people with no reason to take the author’s word.

What “local-first” means

Local-first software keeps your data on your device and treats any network use as optional rather than required. A useful test has three questions:

  1. Where does the data live? On your disk, in a format you can inspect, or on someone else’s server?
  2. What does it do without a network? If the answer is “nothing,” the product depends on a server.
  3. What would a skeptic find? If someone watched its network traffic for an hour, what would they see?

For a system monitor, the right answers are boring on purpose. It reads from your operating system, draws a window, and stores nothing. Open Task Manager’s own comparison with the built-in tool goes into this in detail: Open Task Manager vs. the Windows Task Manager.

Practical steps

  • Prefer tools whose source is public and whose releases can be matched to it.
  • Check what any app sends, using the method in how to check what an app sends over the network.
  • Review the privacy toggles in your operating system after major updates (Windows guide).
  • Be most careful with software that records your activity, because the cost of a mistake is highest there.

The lesson from Recall isn’t that one company got it wrong. It is that software that sees everything should earn trust by being checkable, and that the checking should not depend on goodwill.
