Zombie and Orphan Processes on Linux: What They Are and What to Do

2026-10-11 · sabaoongfx · 3 min read

Sooner or later a Linux user sees a process marked Z or labelled “defunct” and tries to kill it. Nothing happens, however many times they try. That isn’t a bug, and understanding why also explains how processes live and die on Unix-like systems.

How a process ends

When a process exits, the kernel frees almost everything it held: its memory, its open files, its CPU time. But it keeps one small record, the process’s exit status, until the parent process reads it. That reading is done with a system call named wait. It exists so a parent can learn whether a child succeeded or failed.

What a zombie is

A zombie is a process that has finished running but whose parent hasn’t yet read its exit status. It is dead, but its entry stays in the process table. It uses no CPU and (essentially) no memory. The only thing it occupies is a slot, and one process ID.

This is why you can’t kill it: it’s already dead. Sending signals to it does nothing because there is no running code to receive them. The entry vanishes when the parent finally calls wait, or when the parent itself exits.

Are zombies a problem?

Usually not. A few that appear briefly are completely normal. You should care only in two cases:

  • They pile up. A buggy parent that keeps spawning children and never collects them can accumulate thousands, eventually exhausting the available process IDs and blocking new processes from starting.
  • They persist. A zombie that stays for hours points to a parent that is stuck or misbehaving.

What to do about them

  1. Find the parent. In a terminal, ps -o pid,ppid,stat,cmd shows each process’s parent ID. Tools with a tree view, such as htop, make the relationship visible (our comparison).
  2. Ask the parent to behave. Some parents collect children when they receive the SIGCHLD signal.
  3. Restart the parent. If the parent is a stuck service, restarting it clears its zombies (services explained).
  4. Report the bug. If it recurs, the program is failing to reap its children.

Do not kill the parent if it is something critical, such as your session manager or a database, just to remove a zombie. The cure is worse than the condition.

Orphans are different

An orphan is a process that is still running after its parent has exited. Linux handles this automatically: orphaned processes are adopted by the init process (PID 1, usually systemd), which collects them when they end. Orphans are often deliberate. A background service started from a terminal and left running is an orphan, and that’s fine. They are only a concern if you didn’t intend them to keep running; in that case, find them in the process list and end them (safely).

In Open Task Manager

The Details tab lists processes with their status, so zombies show up there if the operating system reports them. We don't yet show parent-child relationships, which is where the tree view in htop is stronger. If you are learning how processes relate, the Details tab together with our beginner’s guide is a good start.
